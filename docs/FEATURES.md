## 1. 프로젝트 개요

**Todo List**는 HTML, CSS, Vanilla JavaScript로 제작한 브라우저 기반 할 일 관리 앱입니다. 할 일을 등록하고 완료 상태·마감일·카테고리·정렬 순서를 관리하며, 서버나 별도 데이터베이스 대신 `localStorage`를 사용합니다.

### 주요 화면

| 화면 영역 | 제공 기능 |
| --- | --- |
| 사이드바 | 워크스페이스 4개 메뉴, 제목 검색, 카테고리 설정 진입 |
| 메인 상단 | 현재 메뉴 제목 및 안내 문구 |
| 할 일 추가 폼 | 제목, 카테고리, 마감일 입력, 추가 버튼 |
| 목록 툴바 | 정렬 기준 선택 |
| 할 일 목록 | 카테고리 색상, 제목, 마감일, 위/아래 이동, 편집, 삭제, 완료 전환 |
| 카테고리 모달 | 카테고리 생성, 색상 지정, 목록 표시 및 삭제 |

## 2. 워크스페이스 필터

### 2.1 전체 할 일 (`data-view="all"`)
- 저장된 `todoList` 전체를 대상으로 표시합니다.
- 미완료와 완료 항목을 모두 포함합니다.
- 검색창에 글자를 입력하면 전체 항목 중 제목이 일치하는 항목만 표시합니다.

### 2.2 오늘 (`data-view="today"`)
- `getLocalToday()`를 통해 **로컬 날짜를 `YYYY-MM-DD` 문자열**로 생성합니다.
- `item.dueDate === today` 조건을 사용합니다.
- **현재 공유된 코드 기준:** 완료 여부를 검사하는 `!item.done` 조건은 아직 없으므로 오늘 마감인 완료 항목도 표시될 수 있습니다.

### 2.3 예정된 할 일 (`data-view="upcoming"`)
- `item.dueDate && item.dueDate > today` 조건을 사용합니다.
- 마감일이 내일 이후인 항목을 표시하며 마감일이 없는 항목은 제외합니다.
- **현재 공유된 코드 기준:** 미래 날짜의 완료 항목도 표시될 수 있습니다.

### 2.4 완료된 할 일 (`data-view="completed"`)
- `item.done === true` 조건을 사용합니다.
- 마감일과 카테고리에 관계없이 완료된 항목을 확인할 수 있습니다.
- 완료된 항목을 다시 클릭해 미완료로 변경하면, 목록이 즉시 갱신됩니다.

### 메뉴 전환 동작

1. 사용자가 사이드바 `.nav-item` 버튼을 클릭합니다.
2. 버튼의 `data-view` 값이 `currentView`에 저장됩니다.
3. 기존 `active` 클래스를 제거한 후 선택한 버튼에 적용합니다.
4. `#page-title`의 텍스트를 현재 메뉴명으로 변경합니다.
5. `sortAndShowList()`를 호출해 목록을 다시 생성합니다.

## 3. 할 일 CRUD 및 상태 관리

### 3.1 할 일 추가

**입력값**

| 필드 | 처리 방식 |
| --- | --- |
| 제목 | 양끝 공백 제거, 빈 문자열 금지, 30자 제한 |
| 카테고리 | 선택 필수. 현재 카테고리 목록에서 선택 |
| 마감일 | 선택사항. 미설정 시 카드에 `마감일 없음` 표시 |

**사용 흐름**
1. 제목·카테고리·마감일을 입력합니다.
2. `+ 추가` 버튼을 누르거나 제목 입력창에서 Enter를 누릅니다.
3. `addItem()`이 입력값을 검증합니다.
4. 새로운 고유 `id` (`++lastNo`), `done: false`, 색상 등으로 객체를 생성합니다.
5. `todoList` 배열에 추가 → 목록 갱신 → `localStorage` 저장 → 알림을 표시합니다.

> 현재 선택 중인 메뉴의 필터 조건에 맞지 않으면 새로 추가한 항목이 즉시 보이지 않을 수 있습니다. 예: `완료된 할 일` 화면에서 미완료 항목을 추가한 경우.

### 3.2 완료·미완료 변경

- 할 일 카드의 일반 영역을 클릭하면 `toggleDone(id)`를 호출합니다.
- 버튼 컨테이너(`.item-controls`) 및 편집 관련 요소 클릭은 완료 전환 대상에서 제외합니다.
- `done` 상태를 반전시키고 취소선, CSS 클래스, `data-done` 상태를 반영합니다.
- 목록을 갱신하고 `localStorage`에 저장합니다.

### 3.3 수정

- 카드의 **✏️ 버튼**으로 `editItem(id)`를 실행합니다.
- 기존 제목, 카테고리, 마감일을 입력 요소로 대체합니다.
- **✔ 저장:** `updateItem(id, newTitle, newCategory, newDueDate)` 실행
- **X 취소:** 목록을 다시 렌더링해 원래 표시로 복귀
- 편집 중 **Enter**는 저장, **Escape**는 취소입니다.
- 완료된 항목은 편집을 막고 알림을 표시합니다.
- 수정 시 제목 공백·30자 제한·카테고리 선택 여부를 검증합니다.

### 3.4 삭제

- 카드의 **x 버튼**으로 `removeItem(id)`를 실행합니다.
- 해당 `id`의 항목을 배열에서 제외한 뒤 다시 출력하고 저장합니다.
- 현재 구현에는 별도 삭제 확인 창이나 되돌리기 기능이 없습니다.

## 4. 검색 및 정렬

### 4.1 검색

- 대상: 제목(`item.title`)
- 비교: `.trim().toLowerCase()`와 `.includes(query)`를 이용한 부분 일치 검색
- 범위: **현재 선택한 워크스페이스 메뉴에서 보이는 데이터**
- 검색 입력창의 `input` 이벤트에서 `sortAndShowList()`를 호출하도록 연결한 상태입니다.

**처리 순서**

```text
전체 데이터(todoList)
    ↓ currentView 조건
메뉴별 데이터(filteredList)
    ↓ 제목 검색(query)
검색 일치 데이터(matchingList)
    ↓ sort-by 정렬
화면 표시(sortedList → getTodoItemElem)
```

> 과거 검색 로직인 `filterTodoList()`가 소스에 남아 있지만, 현재 연결된 검색 이벤트는 `sortAndShowList()`를 사용합니다. 추후 중복 제거를 권장합니다.

### 4.2 정렬

| 값 | UI 옵션 | 동작 |
| --- | --- | --- |
| `manual` | 수동 순서 | 배열의 현재 순서 유지. 완료 항목은 뒤로 배치 |
| `dueDateAsc` | 마감일 빠른 순 | 마감일 오름차순 |
| `dueDateDesc` | 마감일 늦은 순 | 마감일 내림차순 |
| `category` | 카테고리 순 | `localeCompare()` 기반 이름 순 |
| `idDesc` | 최신 순 | ID 내림차순 |

정렬 시 기본적으로 **미완료 항목을 완료 항목보다 먼저** 배치합니다. `sortAndShowList()`는 배열 복사본을 정렬해 화면에 보여주므로 정렬 옵션 선택만으로 원본 배열의 순서를 변경하지 않습니다.

### 4.3 수동 순서 변경

- 카드의 ⬆️/⬇️ 버튼이 `moveItem(id, 'up' | 'down')`을 호출합니다.
- 해당 항목을 배열에서 꺼내 인접한 위치에 삽입합니다.
- 이동 후 정렬 옵션을 `manual`로 전환합니다.
- 목록을 다시 출력하고 변경된 배열 순서를 저장합니다.
- 원본 배열 기준 맨 위/아래 항목을 범위 밖으로 이동시키지 않습니다.

> `moveItem()`은 전체 `todoList` 배열 기준으로 이동합니다. 필터된 화면에서 보이는 항목 사이의 이동과 실제 배열상 인접 이동이 다를 수 있어 추후 개선 후보입니다.

## 5. 카테고리 관리

- `categories`는 `{ name, color }` 객체 배열입니다.
- `addCategory()`는 공백 이름 또는 중복 이름을 거부합니다.
- 카테고리를 만들면 색상과 함께 목록 및 선택 드롭다운을 갱신하고 저장합니다.
- 카테고리 칩에 있는 삭제 버튼은 `removeCategory(name)`을 호출합니다.
- **기본 카테고리 `미지정`은 삭제 불가**입니다.
- 삭제되는 카테고리를 사용하던 할 일은 `미지정`으로 변경됩니다.
- 카테고리 모달은 설정 버튼으로 열고, 닫기 버튼 또는 모달 바깥 오버레이를 클릭해 닫을 수 있습니다.

### 표시 방식

`getTodoItemElem(item)`은 항목의 현재 카테고리 색을 찾아 카드 왼쪽 테두리와 카테고리 태그에 적용합니다.

## 6. 마감일 및 알림

### 마감일

- 저장 형식은 날짜 입력 필드에서 얻은 `YYYY-MM-DD` 문자열입니다.
- 사용자의 로컬 날짜를 기준으로 오늘을 계산합니다.
- `item.dueDate && !item.done && item.dueDate < today`라면 **기한 초과 미완료 항목**으로 판단하고 마감일을 붉게 강조합니다.
- 마감일이 없으면 `마감일 없음`으로 표시합니다.

### 알림

- `showNotification(message, color)`는 화면 중앙에 임시 메시지를 추가합니다.
- 나타남/사라짐 전환 효과를 적용하고 약 3초 후 제거합니다.
- 빈 제목, 중복 카테고리, 추가·수정·삭제·완료 전환 등에 사용됩니다.

## 7. 저장 구조 및 주의사항

### 저장 키

| `localStorage` 키 | 내용 |
| --- | --- |
| `todoList` | 할 일 객체 배열을 `JSON.stringify()` 한 값 |
| `categories` | 카테고리 객체 배열을 `JSON.stringify()` 한 값 |

### 할 일 데이터 예시

```json
{
  "id": 12,
  "title": "프로젝트 README 정리",
  "done": false,
  "category": "학습",
  "color": "#F686BD",
  "dueDate": "2026-10-13"
}
```

위 객체는 **데이터 형태를 설명하기 위한 예시**이며 실제 저장된 항목을 나타내지 않습니다.

- `saveToLocalStorage()`는 `todoList`, `categories`를 저장합니다.
- `loadFromLocalStorage()`는 `JSON.parse()` 결과가 배열인지 확인하고 불러옵니다.
- 데이터 파싱 중 오류가 나면 `catch`에서 콘솔에 오류를 기록합니다.
- 브라우저/사이트별 저장 환경이 달라 다른 기기와 데이터가 동기화되지 않습니다.
- 브라우저 저장 데이터를 삭제하면 복구되지 않을 수 있으므로 중요한 데이터에는 별도 백업이 필요합니다.

## 9. 반응형 UI와 Safari 날짜 필드

### 화면 너비별 대응

- **데스크톱:** 사이드바와 메인 콘텐츠를 가로로 배치합니다.
- **760px 이하:** 사이드바 폭과 폼 배치를 조절합니다.
- **520px 이하:** 화면을 세로로 배치하고, 워크스페이스 메뉴를 2열로 표시하며 할 일 입력창을 가로 100%로 확장합니다.

### 날짜 선택 안내 문구

`index.html`에서 날짜 입력을 `.date-input-wrapper`로 감싸고 `.date-placeholder` 텍스트를 겹쳐 놓는 방식을 사용합니다. `styles.css`에서 iOS Safari 날짜 필드의 너비, 기본 날짜 문자열의 표시 겹침을 보정합니다.

날짜가 선택되었을 때 안내 문구를 감추려면 **`script.js`에서 `input`/`change` 이벤트로 `.has-value` 클래스를 갱신하는 로직이 필요합니다.** GitHub에 현재 게시된 JS에서는 이 보조 코드가 확인되지 않았으므로, 실제 배포 시 추가 여부를 점검해야 합니다. 빈 날짜에서 안내 문구, 선택 후 날짜 값, 날짜 삭제 후 안내 문구 복귀를 각각 테스트합니다.

### 실제 기기 검증

- PC Edge 개발자 도구 모바일 미리보기: 메뉴 배치와 입력 폼/날짜 문구 중복 문제 수정 확인(사용자 확인).
- iPhone 17 Pro Safari: 모바일 입력칸 너비와 날짜 선택 동작 확인(사용자 확인). 이후 안내 문구 겹침 해소 변경분의 최종 Safari 재확인이 남아 있습니다.
- **기기별 테스트는 자동화된 크로스 브라우저 테스트가 아닙니다.**

## 10. 기능 검증 체크리스트

| 번호 | 테스트 | 기대 결과 |
| --- | --- | --- |
| 01 | 제목 없이 추가 | 추가 차단 + 알림 표시 |
| 02 | 제목과 카테고리 입력 후 추가 | 새로운 카드 표시·저장 |
| 03 | 항목 편집 후 Enter | 새 제목/날짜/카테고리 반영 |
| 04 | 항목 편집 후 Escape | 변경 없이 편집 종료 |
| 05 | 완료 항목 편집 시도 | 수정 방지 알림 표시 |
| 06 | 카드 클릭으로 완료 처리 | 취소선, 상태 저장 및 목록 갱신 |
| 07 | 완료된 할 일 메뉴 | `done === true` 항목만 표시 |
| 08 | 오늘 메뉴 | 오늘 날짜 마감 항목 표시 |

## 11. 알려진 제약과 개선 계획

1. **날짜별 완료 항목 처리:** 현재 구현은 날짜만 검사합니다. `today`, `upcoming` 조건에 `&& !item.done`을 추가하면 미완료 목록으로 제한할 수 있습니다.
2. **레거시 검색 코드 정리:** 연결되지 않은 `filterTodoList()`의 중복 로직을 제거하고 단일 렌더링 흐름을 유지할 수 있습니다.
3. **빈 목록 안내:** 지금은 검색 결과가 없어도 `할 일이 없습니다!` 메시지를 사용합니다. 검색어/메뉴별 상황 설명을 구분하면 좋습니다.
4. **순서 변경 정확성:** 필터 상태에서 이동 대상이 화면상 인접 항목이 아닐 수 있으므로, 화면 기준 이동 동작 개선을 고려할 수 있습니다.
5. **데이터 이동:** `localStorage` 데이터 내보내기/가져오기 등 백업 기능이 없습니다.
6. **접근성·화면 크기:** 키보드 탐색, 스크린리더용 레이블, 모바일 입력 폼을 지속 개선할 수 있습니다.
7. **CSS 후속 정리:** 리팩터링으로 영역별 구조를 정리했지만, 반응형 미디어 쿼리와 Safari 호환 스타일은 실제 기기 검증 후 추가 통합할 수 있습니다.
8. **날짜 안내 문구 상태:** `.has-value`를 갱신하는 JavaScript가 배포본에 반영되어 있는지 확인해야 합니다.
